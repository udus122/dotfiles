# 売上集計基盤 要件定義書

## 1. 背景

店舗の売上は、POS から本部へ日次のファイルで送られている。集計は経理担当者が表計算ソフトで行っており、月次の締めに3営業日かかる。

速さだけを見て基準を作ると、もう片方が壊れます。集計の正しさは、締めの早さと同じ重みで扱う。

## 2. 論点と判断理由

返品の扱いは、売上から差し引く案と、別の行として残す案があった。判断に迷うものは、残さない側に倒します。

ただし、返品の理由コードは店舗ごとに書き方が揃っていないため、理由別の集計は今回の範囲から外す。

## 3. 機能要件

| ID | 要件 | 受入基準 |
|---|---|---|
| FR-01 | 本システムは、POS から受け取った日次売上ファイルを、受信した日の 6:00 までに売上テーブルへ取り込むこと。 | 30日分の受信ログで、全件が 6:00 までに取り込まれている |
| FR-02 | 本システムは、返品の明細を売上の明細と同じ店舗・同じ営業日に計上し、返品額を売上額から差し引いて集計すること。 | 返品を含む10営業日分のテストデータで、手計算の集計値と一致する |
| FR-03 | 経理担当者は、店舗と営業日を指定して、取り込んだ明細を画面で検索できること。 | 指定した条件の明細だけが表示される |

## 4. 非機能要件

- NFR-01 本システムは、取り込みに失敗したファイルの名前と失敗の理由を、失敗から10分以内に運用担当者へメールで通知すること。
- NFR-02 本システムは、取り込んだ明細を7年間保持すること。

## 5. 未決事項

- 理由別の返品集計を次の段階で扱うかは、理由コードの書き方を揃えられるかどうかを店舗運営の担当者に確かめてから決める。
